# Guarded recovery input and owned trial shutdown

The recovery wrapper requests one candidate face-button pulse through the
installed virtual controller. It preserves the pinned owner, foreground,
dependency, deadline and neutral/disconnect guards. A fresh ready/GO gate follows
two seconds of neutral controller discovery. South, East and North are separate
fixed candidates; a completed report never means the game consumed the input or
recovered. Dry runs never import the controller package.

The independent fresh judge passed all 15 fake tests and scored the bounded
wrapper 9.5 for engineering correctness and guard preservation. That score is
not BMX Streets likeness; likeness remains unrated. The raw dependency sources
are unchanged, and their narrow LF rule preserves their hashes across checkouts.

The separate owned-trial watcher has no controller or window operation. It
holds the original native process object, revalidates its creation, isolated
image, loaded runtime and file hashes, and bounds lifetime from process creation.
An accepted termination requires two separate signaled-handle observations
before the watcher reports success. Its evidence does not certify gameplay.

Native trial 286 accepted a 5.3883 m/s side impact and detached the bike. The
candidate South controller leg refused before ready because the game lacked
foreground ownership: zero driver reports were submitted. The original watcher
accepted deadline termination but then encountered an image-query/exit race.
The original failed receipt is preserved, and two later CIM observations found
the PID absent. This is neither a controller recovery pass nor a watcher pass.

The repaired watcher rechecks the same held handle when an image/module read or
termination races natural exit. A running failure still fails closed; missing
creation identity never becomes an exit claim. All 2,543 fake assertions pass,
including the actual pure C# observation/termination helpers. Real Windows
interop checks also pass against two hidden child processes created by that
check: natural exit and accepted termination, each with two held-handle exit
observations. This replacement has not repeated the full game deadline test.

Detailed source pins, independent judge records and the failed native receipt
are retained under `build/bmx/overnight-review20261021/` and
`build/bmx/controller-recovery286/`. Computer Use app approval remains required
for the next foreground-controlled visual trial; it previously timed out.

## Native shutdown follow-up

Run 287 exposed a longer pending-exit interval: after accepted termination,
image metadata could already be unavailable while the held process handle was
still unsignaled. An immediate recheck was insufficient. The watcher now uses
an explicit exit-observation phase after its final binding and termination
attempt. That phase reads only the original held handle's wait state and exact
creation identity. It retains the ten-second exit grace and two separated
signaled observations; live binding failures before the attempt still refuse.

The new source passes an independent review and all 3,515 fake assertions.
Native run 288 passes its complete 60-second game shutdown test on source
`CE95AA80EDA9C5A273FD00AC1EFA7B51C65F11C5A6AFCE279CF21A56277A0399`:
the deadline requests termination of the bound game, both exit observations
complete within the grace, and the guardian reports success with no issue.
Two additional CIM observations verify the PID absent. The frozen receipt and
log are in `build/bmx/watchdog-native288/`. No controller input was sent and
gameplay/likeness remain unqualified. Failed 286 and 287 receipts remain intact.
