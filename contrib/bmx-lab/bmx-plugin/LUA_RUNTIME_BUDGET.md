# Lua runtime work and budget boundary

The current inactive Core/Source composition retains the reviewed diagnostic optimization: each diagnostic snapshot gathers one locally cached Source/Spawn/Equipment status, uses it only inside that snapshot, and makes one whole-tree copy of its source subtree. Retained source-step records still copy independently. Ordinary authority checks continue to read current status; no diagnostic cache survives a call, tick, exception or actuator callback. Fixed private validation-key arrays are allocated once per module.

Diagnostic finite-number,1200-character string, depth and3000-field limits remain. Opaque nested values fail closed and whole snapshots remain detached. Storage writes, first-marker handling and permissions are unchanged; the persistence cadence and JSON preflight changes are described below. No VM budget or timeout was relaxed.

Core/Source v3 adds a separate fresh authorization cost when the dormant force seam is tested with qualified scratch copies. A fresh Source authorization calls `lease_read`, `lease_state` and `lease_capture_state` through the selected existing handle. A following tick reads the six readiness facts and those three lease reads at most twice: at its start (Core's own facts and Source's step) and afresh in the check immediately before the force submit. The checks around a contact batch, which publishes nothing, share the tick's start reads (`Source:authorize(frame, true)` judges the step's own rows with no SDK call), and the check after the submit shares the submit's fresh reads. A focus, menu or lease change during the tick is therefore seen before any force is published, but not before a contact batch. Ordinary Source step and once-per-new-report renewal remain separate. Authorization does not adopt model input, renew, read another body or mint native authority.

The S1b in-game per-call timing (a 3.7 ms ride tick, about 1.8 ms inside 97 SDK calls) set four more cadences in the trial composition. A renewable Follow renews on its first following tick and then only while less than 475 ms of Core's lease is left (the 150 ms margin, the longest 250 ms tick gap Core accepts and 75 ms of the next tick's reads), so after the first following tick's renewal it renews none while 475 ms or more is left (about the first 2.5 s of the 3 s base lease), and then about every second tick. The category lane's rider tripwire is cast every second measured epoch; a hit is seen at most one epoch (16.7 ms) later and still stops Ride before that epoch's model and command. Core's ledger is saved at most once a second while following (every state change still saves at once), and its size check encodes the ledger only when `ledger_bound` cannot show that it fits in 48000 bytes. Two force receipts are still read a tick: the newest command's, to see it left the native inbox (a queued one holds the next command), and the oldest's, whose successor sample is what allows its ACK.

The final clock is sampled after authorization, including its elapsed time within the existing500ms qualification boundary. This is sequential sampled validation, not an atomic lease/body transaction. The additional Host/native call cost and the whole plugin's startup/tick budgets remain unmeasured by this package's pure CLI tests. No50ms pass, latency speedup or cause for an earlier timeout is claimed.

Prior isolated diagnostic operation counts are historical component evidence; they are not timings or results of this final package. Fresh exact composed execution belongs to the final artifact's raw receipts. Both Core/Ride source gates remain false and public Mount remains denied; pure fixtures cannot activate the package or establish gameplay parity.
